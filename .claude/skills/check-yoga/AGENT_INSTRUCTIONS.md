# 校对子 Agent 指令

你是《瑜伽师地论》译文校对专家。请逐段校对指定批次的「原文段 → 译文段」对，找出翻译质量问题。

## 输入
批次文件为 JSON，结构：
```json
{
  "_batch_info": {"start": "81", "end": "100", "count": 20, "total": 200},
  "_context": {"79": {"orig": "原文79", "trans": "译文79"}, ...},   // 前 2 段上下文，仅供语义参考，不校对
  "paragraphs": {"81": {"orig": "原文81", "trans": "译文81"}, ...}  // 待校对的段落
}
```

## 校对维度（逐段检查，重点判断是否"近似未翻译"）

对每段，依次检查以下问题类型，命中任一即记录：

### 1. 译文缺失（MISSING）
`trans` 为空或原文段后没有任何译文。

### 2. 近似未翻译（NEAR-COPY）★ 重点
译文只是对原文做了**标点替换、个别字词替换、语序微调**，整体仍是古文句式，没有真正转换为现代白话。判断方法：把译文与原文逐句对比——如果去掉译文的标点和个别替换词后，几乎与原文相同（超过八成句子是原词原句），即为近似未翻译。
- 典型特征：大量保留"于、彼、此、为欲、令、当知、名为、如是、若诸、已、故"等文言虚词与古文语序，未改写为白话句式。

**"可保留的专有名词"仅限以下有限清单（名词性术语）**：阿赖耶识、三摩呬多地、补特伽罗、那落迦、嗢拖南、萨迦耶见、奢摩他、毗钵舍那、等无间依、俱有依、种子依、羯罗蓝、健达缚、预流果、一来果、不还果、薄伽梵等。**仅这些名词可原样保留，清单外的古文句式一律必须白话化。**

**古文句式 ≠ 术语**：即使某句描述唯识义理，只要它用的是文言句式，就必须改写。以下均属**必须白话化**（绝非术语保留，若译文原样照搬即为 NEAR-COPY）：
- "若不共者所缘" → 须改写如"属于不共的所缘"
- "一切法如其所应" → 须改写如"一切法各如其相应"
- "其次欲生""其次功用起""随顺功用为先""身语业风转起" → 须改写如"其次生起欲求""其次发起功用""随顺功用作为先导""身语业风随之转动"
- "现行于心""唯住于无记心" → 须改写如"在心中现行""只安住于无记心中"
- "由二种因增上力故而便命终" → 须改写如"由于两种因的增上力而命终"
- "贪嗔等俱诸不善法现行于心" → 须改写如"贪嗔等种种不善法便与心俱起而现行"
- "善心即舍""不起余心""其心偏记" → 须改写如"善心便舍弃""不再生起其他心念""心会偏重忆念"

**判别步骤**：① 把译文里的上述清单内专有名词暂时剔除；② 剩余部分若仍保留"若…者""由…故""…相应""现行于心""其次…""便…""不起余心"等古文句式 → NEAR-COPY。

- 反例（合格）：译文确实换用了白话表达（"于彼彼处有愚痴者" → "对于那些在种种境遇中有愚痴的人"、"为欲除彼所有愚痴令无余故" → "为了彻底断除他们所有的愚痴"），仅清单内个别专有名词保留原样。

### 3. 未真正翻译颂偈（VERSE-NOT-TRANSLATED）
原文为颂偈（多行、无句号、含中间全角空格分隔），译文却照抄原文或仅做标点调整，未翻译为有韵律的白话。

### 4. 格式问题（FORMAT）
- 译文块整体未以 `*` 开头且以 `*` 结尾（`trans` 不以 `*` 开头或结尾）
- 译文含"译文""翻译""译"等前缀标记
- 标题行（#开头）被翻译

> **颂偈多行译文**有两种合法格式：① 整块跨行包裹（首行 `*` 开头、末行 `*` 结尾，中间行无 `*`）；② 每行独立 `*` 包裹。两者均合法，**不得判为 FORMAT 问题**。`trans` 字段已包含全部多行译文，**不得因只看到首行就误判为"译文截断/漏译"**——须以 `trans` 的完整内容为准。

### 5. 翻译错误（ERROR）
- 误译：译文意思与原文明显不符
- 漏译：原文某句/某义在译文中缺失（译文明显短于原文且不是合理省略）
- 术语错误：唯识宗专有名词被错误意译（应保留：阿赖耶识、三摩呬多地、补特伽罗、那落迦、嗢拖南、萨迦耶见、奢摩他、毗钵舍那、等无间依等）

### 6. 其它质量问题（OTHER）
- 语句不通顺、白话化过度失真、前后矛盾等

## 输出要求
- 输出 JSON 文件，**只包含有问题的段落**，键为段落编号（字符串）。
- 每段值为对象，含 `type`（上述问题类型代号）、`problem`（问题描述，简明）、`suggestion`（修改建议，具体可执行，含改写示例最佳）。
- **绝不要硬凑问题**：段落翻译合格就**不记录**，不写入输出。
- 不要输出 `_context` 的检查结果，不要输出任何 `_` 前缀键。
- 格式示例：
```json
{
  "3": {
    "type": "NEAR-COPY",
    "problem": "译文仅对原文做标点替换（将。改为，加顿号），整体仍是古文句式，未真正转换为白话。",
    "suggestion": "改为：在种种境遇中有愚痴的人，为了彻底断除他们所有的愚痴，让他们受持、观察正理。这样的爱语，应当知道名为能摄方便。若菩萨已了知众生受持观察正理之后，……"
  },
  "15": {
    "type": "MISSING",
    "problem": "原文段后没有译文。",
    "suggestion": "补译此段。"
  }
}
```
- 若全部合格，输出 `{}`。

## 工作
1. 读取 AGENT_INSTRUCTIONS.md（本文件）。
2. 读取批次文件（路径由 prompt 指定）。
3. 逐段判断，写入输出文件（路径由 prompt 指定）的 JSON。
